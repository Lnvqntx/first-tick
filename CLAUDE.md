# First Tick: website spec

## What this is
First Tick is a free, beginner-friendly online event on financial markets and trading, run by the Programming Club of CR Rao AIMSCS (University of Hyderabad campus). Format: 3 learning days (theory), then 1 paper-trading assignment day, then a certificate. Open to all CR Rao AIMSCS students. Optional Python track (plot a chart, backtest a moving-average crossover).

This repo (`Lnvqntx/first-tick`) is the event website. Primary job of the site: get students to register and join the WhatsApp community, then serve the daily PDFs and the final submission link.

Audience: first- to fourth-year students, mostly on phones. Many have never traded.

## Tech
- Vite + React + TypeScript + Tailwind CSS, static output, deployed on Vercel (free). No backend in this repo.
- `react-router-dom` for three routes: `/` (single long landing page), `/resources`, `/verify`.
- Self-host fonts with `@fontsource` (no Google Fonts CDN calls).
- Keep dependencies minimal. No UI kit that forces a generic look.

## Content that must be easy to change: `src/config/event.ts`
Everything the club will edit lives here, typed and commented:
- `name`, `tagline`, `clubName`, `collegeName`
- `datesConfirmed: false`. When false, show the dates with a small "Dates to be confirmed" note everywhere they appear. Flip to true to remove it.
- Days (timezone IST, +05:30):
  - Day 1: 27 Oct 2026, Markets and basics
  - Day 2: 28 Oct 2026, Analysis and market movers
  - Day 3: 29 Oct 2026, Risk, strategy and practice
  - Day 4: 30 Oct 2026, Paper-trade assignment submission (deadline time TBD, use a placeholder)
- `links`: `registrationForm` (Google Form), `whatsappCommunity` (one WhatsApp community link), `submissionForm`. All empty strings for now. External links open in a new tab (`rel="noopener noreferrer"`). Any button whose link is empty renders as visibly disabled with a "Link coming soon" state, never a dead click.
- `clubLogo`, `heroLine`, `marquee`, `challenge`, `steps`: copy and assets for the landing page.
- `resources`: one entry per item (Day 1, 2, 3 PDFs, assignment brief, Python notebook) with `{ id, title, day, availableOn, file: string | null }`. `file: null` means locked or coming soon.
- `recordingUrl: null`. Only render a "Recorded session" card if this is set. Do not show it otherwise.
- `faq`: array of question and answer.

## Design direction (follow this)
Black and gold with market energy. Premium and cinematic, like a live trading desk at night, glowing but classy, never neon. Not a copy of any other course site (no borrowed layouts, no blue or purple UI, no 3D shapes).
- Palette (adjust slightly if contrast demands): ink `#0B0A08`, surface `#151311`, line `#2A2620`, gold `#E3B23C`, deep gold `#B8892B`, text `#F3EEE3`, muted `#A39D8F`. Market colours: up green `#2FBF71`, down red `#E5534B`, used in charts (hero chart, schedule candles, certificate seal).
- Gold: a rich gold gradient (`#F7D77E` → `#E3B23C` → `#B8892B`) on primary buttons, the wordmark "TICK", the selected schedule candle, the Day 4 outline and the certificate card. Soft gold glow on hover and focus.
- Hero glow: slow-drifting blurred colour glows behind the transparent chart canvas (warm gold, emerald, a hint of magenta at low alpha, hero only), a gold bloom behind the wordmark, a subtle glow on FIRSTTICK, and a slight bloom on candles and the price line. The dark centre vignette stays so hero text is AA.
- Shapes: every button and chip is a full pill (`rounded-full`), including the nav Register button and the resources tabs. Cards are softly rounded (`rounded-3xl`), FAQ rows `rounded-2xl`.
- Type: two clearly distinct, non-default families (Fraunces for display, IBM Plex Sans/Mono for text). Bold, large display type; secondary copy in muted so headings pop. Sentence case for headings and labels. Body lines under 75 characters. Defined type scale in `tailwind.config.js`.
- Logo and wordmark: the Programming Club seal (`public/brand/logo.png`, generated by `npm run logo` from `public/brand/programming-club-logo.png`) next to "FIRSTTICK" with "TICK" in gold. The seal is black with white rings, so it always gets a thin light ring and soft glow (`.logo-seal`). Used in the header, footer, certificate card and favicons.
- Motion (all off or static under `prefers-reduced-motion`):
  1. the hero's live simulated chart and its drifting colour glows (static chart plus crosshair when reduced);
  2. the two tilted marquee bands (static wrapped lists when reduced);
  3. the schedule candles grow in once;
  4. scroll reveal: `[data-reveal]` elements fade in, rise 14px and go from 4px blur to sharp once, staggered, about 500ms; plus a slim gold scroll-progress bar at the top;
  5. cursor-reactive outlines: every `.glow-edge` element (cards, chips, FAQ rows, bordered buttons) gets a gold border highlight that follows the pointer, a tilt of up to 4° and a 3px shift, easing back on leave. One hook (`useCursorGlow`), transform and opacity only, off on touch devices.
- Layout: generous spacing. The hero is centred; other sections are left-aligned. Avoid identical template card grids (the challenge pair is deliberately unequal; the three steps are a real numbered sequence), tracked all-caps eyebrow labels, "01 / 02 / 03" numbering (numbers only for Day 1–4 and the three join steps) and decorative gradient washes outside the hero.
- Page length: the landing page should stay around 6 screens or fewer at 1440×900. Keep copy short.
- No stock photos and no AI-generated campus or office images.
- Quality floor: responsive from 360px up, visible keyboard focus, AA contrast (including text over the hero chart), semantic HTML, alt text, fast first load.

## Pages and sections

### `/` Landing (in this order)
1. Header: club seal + FIRSTTICK wordmark, nav (Schedule, Challenge, How to join, FAQ, Resources), pill Register button (goes to the three steps).
2. Hero (full viewport):
   - Behind the content, a full-bleed transparent `<canvas>` candlestick chart streaming a SIMULATED price feed: a tick every ~100–150 ms, candles forming and scrolling left, a smooth gold live-price line, faint grid, small volume bars along the bottom, with drifting colour glows underneath.
   - Pointer interaction: a crosshair follows the cursor (or touch point) with a price label on the right axis, and the live price drifts toward the level under the pointer's Y. When idle the feed keeps running on its own.
   - Dark vignette overlay so text stays AA-readable. Tiny label: "Simulated chart, not real market data".
   - Performance: requestAnimationFrame, devicePixelRatio and resize handled, paused when the tab is hidden or the hero is off-screen, candle count capped by width.
   - Content, centred: a pill chip "Programming Club, CR Rao AIMSCS | 27–30 Oct 2026" (with the "Dates to be confirmed" note from config), a huge glowing "FIRSTTICK" wordmark, one line of at most 12 words (`heroLine`), and two pill buttons: "Register now" (`links.registrationForm`) and "Join WhatsApp" with the WhatsApp glyph (`links.whatsappCommunity`).
3. Marquee bands (from `marquee` in config): two full-width bands tilted about 2°, slightly overlapping, scrolling right to left on a seamless duplicated track. Band 1 bold solid text (themes), band 2 outlined text, dimmer and slower (skills). Gold star separators. Slow down on hover.
4. Schedule: a horizontal row of four candles for Day 1 to Day 4 joined by a thin trend line. Days 1–3 rise and are green; Day 4 (assignment) is a hollow gold outline. Under each candle: day label, date, short title. Each candle is a real `<button aria-pressed>`; hover, focus or click shows that day's topics (max 3 bullets) in one panel below. Day 1 selected by default.
5. Final challenge and certificate (`challenge` in config): headline "Make your first trade. On paper.", then two large cards side by side (stacked on mobile): "Final trading challenge" with four short items, and a gold-gradient "Certificate of completion" card with the wordmark, club seal, the two tiers (Completion and Merit), a decorative seal and a note that the certificate has a verifiable ID. One screen tall.
6. Three steps to your first tick (`steps` in config): (1) Register, "Open form" button; (2) Join the WhatsApp community, WhatsApp button; (3) Show up on the Day 1 date, with a date chip from config (and the dates note while unconfirmed).
7. FAQ: accordion from config, at most 6 questions with 1–2 sentence answers.
8. Footer (compact): club seal and credit, one WhatsApp community link, Resources link, the final Register now button, and the disclaimer.

Registration happens only through the Google Form (`links.registrationForm`); there is no in-page form. Certificates appear only as the challenge section's card; `/verify` stays in the repo, unlinked.

### `/resources`
Tabs: Day 1, Day 2, Day 3, Assignment, Python track. Each item shows a locked state ("Unlocks on 27 Oct", dates from config) or an unlocked state (Download, plus an in-page PDF view via `<iframe>` or `<object>` with a download fallback) based on whether `file` is set. Also show an "Open submission form" button on the Assignment tab, disabled until `links.submissionForm` is set. Include a short note on the assignment page about the expected PDF format (annotated chart, entry/stop/target, risk-reward, position size, short justification).

Important: date-based unlocking in the browser is only cosmetic. The real unlock is that a day's PDF is not committed to `public/resources/` until its morning. Document this in the README.

### `/verify` (kept, currently not linked from the site)
Input for a certificate ID. Look it up in `public/certificates.json` (array of `{ id, name, tier, date }`; ship a file with two clearly fake sample entries). Show name and tier, or a clear "No certificate found for this ID" message. Normalize case and whitespace.

## Registration
Registration is a Google Form owned by the club. The site only links to it (`links.registrationForm`, new tab). No form, endpoint or personal data handling lives in this repo.

## Legal and trust
- Footer on every page: "First Tick is an educational event by the Programming Club, CR Rao AIMSCS. Nothing here is investment advice. All practice is paper trading, and trading involves risk of loss."
- Never imply guaranteed returns. No stock tips, no performance claims.
- Do not use any other organisation's name, logo, PDFs, text or images (for example any other college's trading course). All copy is original.

## Repo hygiene
- Create a `README.md`: what the site is, run and build commands, how to edit `src/config/event.ts`, how to add a day's PDF, how to deploy to Vercel, and the "real unlock" note.
- Commit in small logical steps with clear messages. Push to `main` at the end of each step.
- Add `.gitignore`, `.env.example` (if any env is used), and a simple lint and typecheck script. Run `npm run build` and fix all errors and warnings before saying you are done.

## How to work
1. First write a short design plan (palette, fonts, layout wireframe in ASCII, the hero moment) and check it against the "avoid" list above. Revise anything that looks like a default template look, then build.
2. Make reasonable assumptions instead of asking me questions. List every assumption in the README under "Assumptions".
3. Build in this order: project setup and config, layout and hero, the rest of the landing page, `/resources`, `/verify`, README and docs.
4. After building, run the dev server, check the pages at 360px and 1280px widths, and fix visual issues.

## Definition of done for this phase
- All three routes work, with locked and unlocked states and disabled-link states working from the config alone.
- `npm run build` passes with no errors.
- No fake statistics, testimonials or third-party branding anywhere.
- Content is easy to update from `src/config/event.ts` without touching components.
